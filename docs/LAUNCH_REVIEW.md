**当前最应补的证据：** 一个真实需求用户从团队商品入口购买、安装、产出第一期字幕，

## 双期试用怎么测

先选同一创作者、同一系列的两段授权短片。记录字幕长度、语种、模型/Agent、规则数量和人工编辑耗时；
第二段保留“未应用经验”和“应用后”两份快照，让创作者检查术语、句意和时间轴。
分别计数：触发了几条规则、正确改了几句、误改几句、仍需修改几句。
**只报告这组素材的实测结果**，不把样例的 2/3 改动比例写成准确率或效率提升。
对比耗时需要在相同操作口径下计时，记下是否熟悉素材；无法公平比较时只展示逐句证据。

可使用下面的本地表头；不要将填有订单或用户资料的工作表提交到公共仓库：

```csv
匿名试用编号,来源渠道,系列场景,版本,语种,素材授权,真实购买状态,权益交付状态,安装成功,第一期交付,第二期交付,正确改动句数,误改句数,剩余待改句数,人工校对分钟,证据存放位置,用户反馈,是否同意公开案例
```

公开证据只用匿名编号，订单原件留在平台或受控团队空间。退款、取消、无效交易分别保留状态，
付费用户按独立用户去重，成交与退款统计以平台有效记录和赛事口径为准。

## 可直接使用的招募话术

“我们做了一个给系列视频创作者用的字幕 Skill：把改过的术语、片尾表达和查过的资料留下来，
下一期先给你看逐句改稿和依据，确认后再应用。想找正在做课程、访谈或知识视频的人试两段自己的素材。
我们关心的是它能否少让你重复改同一种错误，也欢迎直接说不好用。需要本地 Python 环境，
可先看免费原创演示；有需要再通过团队 SkillPay 商品购买。不会要求提供私人视频或为了参赛购买。”

发布前把“团队 SkillPay 商品”替换为经验证的新商品链接。用户决定是否购买；不代发消息。

## 3 分钟路演

| 时间 | 展示 | 一句要点 |
|---|---|---|
| 0:00–0:25 | 同一系列反复改术语的场景 | 我们要减少重复校对，而不只是在视频上再加一层字幕 |
| 0:25–1:10 | 打开实际生成的 demo 与改前预览 | 改稿/词库进入候选，测试后才生效；每句能看依据 |
| 1:10–1:40 | 课程改动、房产反例、真实联网术语 | 适用范围不同，结果不同；联网有可检查的来源 |
| 1:40–2:05 | 拦截和撤回 | 旧版本或改过的字幕不能直接沿用验证；出错可以恢复 |
| 2:05–2:35 | 正式团队商品购买到安装/交付的实录 | 只有链路实际跑通后才展示；目前这段仍待补，不能用 mock 冒充 |
| 2:35–3:00 | 独立用户连续两期结果 | 只说实际人数、有效成交和素材范围；缺数据时明确仍在验证 |

## 投稿前最低完成条件

- 最新 CI 全部通过；交付 ZIP 可在独立环境安装；版本、哈希与 PR 对应。
- 团队报名账号与商品归属核对，新商品真实审核通过；从购买入口到下载/安装可用。
- 试用样例、测试样例、平台交易、作品互动分别展示，不混算。
- 素材与代码有权使用；用户案例经同意；官网明确禁止虚假交易和刷量。
- 12.01 报名截止、12.09 提交截止以赛事页当时规则/时区为准；技术提交不等于自动完成报名。
